# Изменения

Версия продукта равна номеру последнего сданного упражнения. По записи на
упражнение: что добавилось, что сломалось бы без миграции, во что обошлось по
цене хода.

## v17 — источники через MCP (в работе)

Механизм `mcp`: те же шесть инструментов Википедии и GBIF, но путь до них —
через MCP-сервер `v16`, отдельный процесс. Нового результата нет, блока в
запросе нет — это новый путь до существующего источника.

- `internal/mcp` — клиент как `tools.Source`: `initialize` → `tools/list` →
  сверка отпечатка описаний с локальными (расхождение — `ErrDrift`, бинарник
  устарел). Пропускаются только шесть инструментов источников, лишние — в
  журнал. Ответы помечены как недоверенные (`Untrusted`), вызов в журнале —
  «через MCP». Сбой транспорта модель получает словами: «MCP-сервер
  недоступен: …».
- Процесс сервера запускается лениво — первым ходом с `mcp`; с выключенным
  механизмом процесса нет вовсе. Поиск бинарника: флаг `-mcp-server` → рядом
  с приложением → `PATH` → сборка `./cmd/animals-mcp` из исходников (предел
  60 с). stderr сервера — в журнал приложения с префиксом `mcp:`. Упавший
  сервер поднимается следующим вызовом; больше трёх перезапусков в минуту —
  отложен на 5 минут.
- Путь выбирается на старте хода и внутри хода не меняется. Сервер не
  поднялся — ход идёт в процессе, в журнале причина, в `Effective` хода
  `mcp=false`.
- Журнал: `mcp.connect` (сервер, версия, протокол, pid) и `mcp.tools`
  (инструменты со схемами) на каждом ходе с MCP. Окно «MCP-сервер» и значок
  статуса на пульте (`ready/dead/drift/unavailable`), API `GET /api/mcp`.
- Запись в `features`: транспорт, по умолчанию выключен.
- Испытание И-7 в `-report`: дорожки A (через MCP), B (в процессе) и B′
  (повтор B, шум модели) на запросах И-1, разделах, узле дерева и
  сравнении; на A сервер убивается посреди вызова. Проверки: описания
  инструментов в запросах A и B совпадают побайтно, постоянная часть A − B
  = 0, вызовы источников A — 100 % через MCP и сходятся со счётчиком
  сервера, B — 0 %, пороги И-1 на обеих дорожках, брака нет, после
  убийства модель получает «MCP-сервер недоступен», следующий ход идёт
  через перезапущенный сервер. Отчётные числа — время A/B, кэш, холодный
  старт, накладные на вызов, HTTP-запросы к источникам (`server_info`
  отдаёт `http_requests`), тексты ошибок, совпадение вызовов A/B и B/B′.

- id вызова кодом (`pre_…`) теперь выводится из агента, инструмента и
  аргументов, а не из общего счётчика: тот же вызов даёт те же байты
  запроса на обоих путях и в любом прогоне — кэш префикса не сбивается.

Совместимость: у старых диалогов ключа `mcp` в наборе механизмов нет — он
выключен, миграция не нужна. Формат файлов не менялся.

Цена хода: 0 токенов, 0 запросов к модели, кэш префикса не трогает —
описания инструментов те же побайтно. Цена вне модели: второй процесс,
задержка JSON-RPC на каждый вызов источника, второй кэш источников в
процессе сервера.

НТ-1 («один файл») теперь выполняется как `go build ./...`: приложение
плюс бинарник сервера рядом с ним. Без бинарника приложение соберёт сервер
само при первом ходе с `mcp`, если рядом исходники и Go.

## v16 — MCP-сервер источников

- `cmd/animals-mcp` — MCP-сервер (stdio, `github.com/modelcontextprotocol/go-sdk`)
  с шестью инструментами источников: регистрирует те же объекты, что
  приложение вызывает в процессе, — описание, схема и исполнение из одного
  места. Ошибка инструмента — результат с `isError`, а не сбой протокола.
  Служебный `server_info` — версия, pid, адреса источников, счётчики
  вызовов. Флаги `-wiki-base`/`-gbif-base`, `-v` — журнал вызовов в stderr.
- `cmd/mcp-list` — минимальный MCP-клиент для независимой проверки
  протокола: рукопожатие, список инструментов со схемами, вызовы, ручной
  режим (`-i`).

## v15 — базовая версия (2026-09-23)

Пятнадцать механизмов в одном продукте: справочник по животным, с которым
разговаривают.

Приёмка: `-report` на `deepseek-v4-flash` — И-1…И-6 приняты, 34 проверки из
34, прогон $0.29 за 13 минут (`examples/report.md`). Длинный диалог — 3,0
запроса к модели на ход, постоянная часть запроса ≈4,1 тыс. токенов, доля
кэша ≈80 %.

- Каркас: сервер на `127.0.0.1`, SSE, фронтенд в `embed`, клиент DeepSeek с
  инструментами.
- `internal/store` — версии файлов (`"schema": N`), цепочка миграций, копия
  `<имя>.v<N>.bak` перед первой перезаписью старого формата, отказ читать
  файл новее кода.
- `internal/features` — реестр механизмов: выключатель, место блока в
  порядке устойчивости, цена по трём статьям. Набор механизмов — свойство
  диалога, а не сервера.
- Границы: свод И-1…И-6 в `invariants/guide.json` (`internal/invariants`,
  вид файла «свод», `"schema": 1`) первым блоком запроса, сверка
  `invariant_check` и процедура `invariant_amend` (propose → accept словами
  человека не раньше следующего хода → decline; снятое правило — `retired`).
  Страж (`guard`) после хода: код отбирает фрагменты по словам свода, судья
  без промпта агента и истории решает, нарушен ли свод; нарушение заменяется
  отказом из полей свода и в историю не попадает. Выключенный `charter`
  даёт те же правила дословно абзацем системного промпта. Цена: блок свода
  ≈1,4 тыс. токенов, судья — только когда код нашёл подозрительное.
  Приёмка И-5 — тесты `internal/charter` и `internal/extract`.
- `internal/bench` — стенд дорожек и опыт `-report`: испытания И-1…И-6 по
  разделу 13 ТЗ с жёсткими проверками и отчётными числами, место под И-7
  (MCP). Стенд не запускается, если дорожки отличаются не ровно одним
  механизмом — ни при двух, ни при нуле; повтор дорожки и другой собеседник
  с тем же набором помечаются явно. У каждого испытания свой каталог данных.
  Отчёт показывает разбивку запроса по блокам механизмов, постоянную часть,
  долю кэша, брак (`Effective ≠ Requested`) и калибровку оценщика по `usage`
  с допуском 5 %. Памятники `testdata/legacy/` сверяются на потерю текстов.
- Флаги `-report`, `-trials`, `-report-out`: прогон испытаний на живой
  модели вместо сервера, отчёт в `examples/report.md`. Сборка приложения
  вынесена в `app.go` — сервер и стенд собирают одно и то же.
- Бюджет «≤ 4 запросов к модели на ход» (И-6: было 4.7 на длинном
  диалоге). Шаги без выбора делает код, механизмы не выключены:
  поиск по названию до первого запроса к идентификатору и чтение раздела,
  чьё название совпало с темой, до специалиста (`agent.Preload` — тот же
  путь, трекер, журнал и пометка источника, что у вызова моделью);
  `match_taxon` идентификатора сразу приносит русские названия, отдельного
  `vernacular_names` у него нет; латынь с автором и годом — та же сверка, без
  отказа и повторной сдачи; извлекатель не зовётся на вопрос о животном без
  слов о человеке, форме ответа и подборке (`extract.Nothing`, пропуск — в
  журнале); привратник не судит второй раз название, о котором ветка уже
  решала. Открытие карточки — 4 запроса вместо 6, клик по разделу — 1 вместо
  2–3, длинный диалог И-6 — ≈3 на ход по сценарию подставной модели.
  Без `collection.state` порядок подборки уходит ведущему словами: раньше
  «Собери подборку» он понимал как «открой всё сразу» (31 запрос за ход).
  Цены блоков в реестре — по измерениям И-6.
